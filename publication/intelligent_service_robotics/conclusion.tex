We measured what a learned examination order does to a complete parallel-jaw grasp planner, in simulation, with two confirmations on EGAD objects whose methods, hypotheses and analysis were frozen in Git before any confirmatory object was planned. The efficiency result replicated: the learned orders examined \confPoneRatio{} and \nxConeEff{} times as many candidates as the original planner, and adding the robustness and centring terms kept the number of examined candidates within the pre-specified margin of the plain learned order. The round-robin fallback never examined more than its bound of $\min(2N_L-1, 2N_D)$ candidates. Robustness was non-inferior to the original planner's in the second confirmation and only fragilely so in the first; the robustness and load-tolerance gains that motivated the robustness terms in development did not replicate, including the multi-friction advantage for which the second method was selected. With the models evaluated inside the planner, the learned order no longer doubles the planning time, but it did not reduce it either. Frozen vision foundation-model features did not reduce the number of examined candidates, and GPD's pretrained classifier was a poor examination order for this planner. The defensible message is therefore a narrow one: learned ordering reliably saves planner evaluations across object populations, while claims of better robustness or faster planning need evidence that this study did not find. Real-robot experiments and calibrated contact parameters are the necessary next steps.
