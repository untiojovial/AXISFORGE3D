## Distinctions and candidate formalism

- A deep kernel composes a feature network and a valid base kernel: `k_theta(x,x') = k_phi(f_w(x), f_w(x'))`, theta=(w,phi). For a deterministic shared map, any PSD base kernel produces a PSD Gram matrix. DKL does not itself imply episodic training, transfer, or adaptation. A GP posterior remains conditioned on observed data and its predictive variance depends on kernel and observation noise; learned features alone do not guarantee calibrated epistemic uncertainty.
- Deep kernel transfer reuses representations and/or kernel parameters across tasks, optionally fine-tuning on a new task. A frozen feature extractor and a fine-tuned extractor are different baselines; neither by itself specifies a meta-learning objective. Approximate deep feature kernels are a separate family; the exact meaning and relationship to the named paper must be established from its original text, not inferred from a similar acronym.
- Adaptive deep kernel fitting denotes task-specific fitting within an adaptation procedure. It must not be conflated with either ordinary joint DKL training or the implicit function theorem (IFT). ADKF-IFT denotes a particular method only after matching its paper's exact inner/outer losses, optimized variables, approximations and inference procedure. The spelling ADFK-IFT in the request needs source verification; do not silently treat it as authoritative or as a distinct algorithm.
- Generic bilevel formulation (illustrative, **not asserted to be the paper's exact formulation**): task tau has support S_tau and query Q_tau, inner `u*_tau(theta) = argmin_u L_in(u,theta; S_tau)` and outer `J(theta)=E_tau L_out(u*_tau(theta),theta; Q_tau)`. If the stationary point is differentiable, Hessian `H = ∂²L_in/∂u²` is nonsingular and regularity conditions hold, `du*/dtheta = -H^{-1} ∂²L_in/(∂u∂theta)`. Hence `dL_out/dtheta = ∂theta L_out - (∂u L_out) H^{-1} ∂²L_in/(∂u∂theta)` (row-gradient convention). In code solve `H^T v = (∂u L_out)^T` rather than form an inverse. IFT is a differentiation tool; an unrolled finite-step gradient is a different estimator, and neither automatically makes a procedure ADKF-IFT.
- These formulas are local: nonconvex inner objectives may have multiple stationary points, an approximate optimizer may not meet stationarity, and singular/indefinite or ill-conditioned Hessians can invalidate or destabilize the calculation. Damping, iterative solves and stopping criteria change the numerical approximation and must be disclosed. Test the linear solve residual and sensitivity; fail explicitly on non-finite or unsolved cases.
- A multimodal representation may map each modality independently, e.g. `z_x=f_x(x)`, `z_c=f_c(c)`, then fuse them with a declared, dimension-checked operation. Independent transforms do not imply statistical independence. Concatenation, addition and product kernels encode different assumptions. Missing modality handling and normalization must be learned solely from allowed training data. External embeddings are inputs with provenance and model version, not evidence that a foundation model has been trained or validated in this project.
- Multi-task GPs, e.g. `k((x,t),(x',t')) = B[t,t'] k_x(x,x')` with PSD B, encode task covariance explicitly. Contextual BO conditions predictions on available context and optimizes decisions for a specified context; a context vector is not automatically a task covariance model or a causal description.

## Guardrails and provisional evaluation

Split by independent object/task or another scientifically justified group **before** fitting encoders, normalization, task memory, hyperparameters or deciding seeds; reserve whole held-out tasks and a final untouched evaluation set. Within each training episode, separate support from query; in online BO construct context and memory from metadata and observations available strictly before the decision time. Carry timestamp and provenance with every feature and memory entry; reject future outcomes and accidental held-out object identifiers. If the same object appears in multiple partitions, observations are correlated and task-level generalization cannot be inferred. Evaluate alternate task orders and freeze evaluation configuration before final test.

Compare equal support sizes, evaluation budgets, initialization, search spaces, computational budgets, objective direction and information access. Use independent seeds, report distributions, confidence intervals and negative transfer as well as favorable outcomes. Distinguish posterior uncertainty within a run from variation across runs. Include ablations: no context; context with permutation or irrelevant/noisy context; no transfer; frozen vs fine-tuned encoder; shared vs task-adapted GP hyperparameters; no memory vs time-safe memory; joint vs independent modality transforms; implicit vs explicitly unrolled gradient on a small controlled problem. Measure predictive log likelihood, calibration and optimization regret, with wall time and failures. These are proposed studies, not executed results.

## Proposed validation before implementation approval

1. Check kernel symmetry and PSD on finite inputs (up to a precision-justified tolerance); test feature dimensions, dtype, finite values and missing modalities.
2. On a small smooth, strongly convex inner problem with a known solution, compare implicit derivatives with analytic derivatives and central finite differences; separately compare unrolled optimization as convergence increases. Check stationarity, Hessian-solve residual and finite-difference step sensitivity. Test singular/ill-conditioned Hessians, repeated points, short support and NaNs, requiring a documented failure rather than a silent result.
3. Compare task GP posterior mean, variance and marginal likelihood with an independent reference under identical noise and normalization assumptions. Define whether uncertainty includes observation noise.
4. Construct leakage tests with deliberately injected future outcomes and overlapping object identities, and adversarial tests with unrelated tasks that induce negative transfer. Check checkpoint provenance and deterministic behavior under declared backend/device settings.
5. Obtain and study thesis and original papers, then write a source-linked traceability matrix identifying exact equations, preprocessing, split, objective, numerical approximations and discrepancies; independently audit before claiming fidelity. On 2026-11-25 the four previously inspected code files were fetched at that commit and compared byte-for-byte with the `main` versions inspected; all matched. The pinned README was also fetched. This is source traceability, not execution or experimental reproduction.

Inspection of [adaptive_dkt.py](https://raw.githubusercontent.com/Wenlin-Chen/ADKF-IFT/b82497e1382e4edd821d1c6132d080035b456884/fs_mol/models/adaptive_dkt.py), [adaptive_dkt_utils.py](https://raw.githubusercontent.com/Wenlin-Chen/ADKF-IFT/b82497e1382e4edd821d1c6132d080035b456884/fs_mol/utils/adaptive_dkt_utils.py), [cauchy_hypergradient.py](https://raw.githubusercontent.com/Wenlin-Chen/ADKF-IFT/b82497e1382e4edd821d1c6132d080035b456884/fs_mol/utils/cauchy_hypergradient.py), and [adaptive_dkt_train.py](https://raw.githubusercontent.com/Wenlin-Chen/ADKF-IFT/b82497e1382e4edd821d1c6132d080035b456884/fs_mol/adaptive_dkt_train.py) reveals the following FS-Mol path:

- The feature extractor takes combinations of graph features, molecular fingerprints and/or descriptors, concatenating enabled features before an optional shared FC network; the default configuration shown is `gnn+ecfp+fc`. Feature extractor parameters and GP-prefixed parameters are partitioned for outer and inner optimization. This is a concrete molecular implementation, not a general independently transformed modality architecture.
- Each sampled task initializes/reinitializes a Gaussian-likelihood exact GP using support features and labels, then calls `fit_gpytorch_scipy` on its exact marginal log likelihood. The functional inner loss is negative support MLL; the outer training loss selected in this path is negative joint predictive log probability of query labels conditioned on the support set, with the GP likelihood included. These map to generic `u` = GP parameters and `theta` = feature extractor parameters above. Training accumulates task hypergradients and updates feature extractor parameters; query outcomes are meta-training supervision, not allowable information in a held-out decision.
- The hypergradient function explicitly assumes that inner minimization has already occurred. It constructs a dense inner Hessian and mixed derivative tensors via autograd, solves a Hessian linear system, and subtracts the correction from the direct outer gradient. This is consistent with the generic IFT formula above under the stated regularity and stationarity assumptions. The code includes `ignore_grad_correction` as an ablation. The inspected implementation solves `H v = gradient` (symmetry of a smooth Hessian makes this equivalent to transposed solve mathematically). It does not establish convergence to a minimum, guarantee Hessian invertibility, or prove calibration; its optional sanity check is not a substitute for a residual or conditioning test. Its dense Hessian approach has scaling limits.
- For classification, this path converts Boolean labels to ±1 and uses a Gaussian likelihood; evaluation applies a sigmoid to predictive mean. Do not present it as exact Bernoulli GP classification or equate sigmoid of mean with full posterior-integrated probability. Regression and classification branches are distinct.

This targeted source review does not validate the code by execution, resolve theorem assumptions or establish equivalence to the thesis. A faithful reproduction still requires complete method, dependency, data, and experiment verification against the paper, appendix and pinned code. ## Bounded design submitted for review

A Python NumPy/SciPy component may keep encoded decisions and immutable externally supplied contexts in explicit separate schemas, composing them only for a contextual surrogate while optimizing over decisions with context fixed. A deterministic feature-map wrapper over an established PSD base kernel can express the kernel composition, but an arbitrary callable is not presumed deterministic or serializable; enforce/declare its dimensions and provenance, and do not label it trained DKL. A task memory must distinguish observation availability time from decision time, require comparable present timestamps, filter strictly earlier available records, and define group exclusion; immutable copied records do not by themselves prevent leakage introduced at fit time. Define checkpoint behavior explicitly rather than serializing arbitrary executable callables. Test routing, shape/nonfinite errors, covariance symmetry/PSD with a valid base kernel, temporal/group boundaries and no-context regression. Auditor design feedback requested these safeguards; Initial implementation, numerical tests and independent review are tracked below; full validation remains pending. No ADKF-IFT implementation is proposed until differentiable optimization and hypergradient validation are available.

## Paired contextual transfer development benchmark

`experiments/contextual_transfer_benchmark.py` ran 30 paired seeds per scenario and method, using eight actual sequential current-task ask/tell evaluations and the same seed and search pool size. Four prior source evaluations are imported only through `ContextMemory.warm_start` with explicit source allowlisting and target-group exclusion; no held-out target observations enter memory. Historical evaluations count in the optimizer's total budget, but each method receives the same eight *new* target evaluations. The baseline is cold context BO; the two transfer arms use source contexts as given or cyclically permuted. Source contexts are deliberately synthetic and independent of the source objective, so this permutation is a software/transfer ablation, not a realistic contextual task distribution. A preliminary exploratory script was run before this benchmark design, so this is a development comparison, not a preregistered confirmatory experiment.

The complete 180 outcomes, per-evaluation regret trajectories and per-run elapsed times are in `experiments/contextual_transfer_results/raw.csv`; configuration and 10,000-resample paired bootstrap percentile intervals are in `summary.json`. Regret is squared distance from the known target optimum, measured on current-task points only. Related-history contextual mean regret minus cold was +0.00000636 (95% percentile interval −0.00000087 to +0.00001669); adversarial-history difference was +0.0009126 (interval +0.00000883 to +0.002692). Positive differences mean higher regret. These results do not establish beneficial transfer on this problem, and the adversarial case illustrates negative transfer for this design. The small deterministic single-family setting, observed extreme-seed sensitivity, arbitrary source contexts and limited sample size constrain generalization. GPU, real tasks and other benchmarks were not evaluated.

Memory serialization produces JSON-compatible copied records and validates on load; it does not authenticate clocks or prove that upstream feature preprocessing avoided future data. Empty eligible histories support cold fallback. Configure each `Modality` with ordered input and feature dimensions, frozen/trainable policy, version and SHA-256. ## Nonlinear task-adaptive prototype

`nonlinear_meta.py` implements a separate CPU/float64 two-layer tanh MLP feature map, support-set exact GP negative marginal likelihood, and joint observation-predictive query negative log likelihood. The inner BFGS fit adapts three GP log parameters per task; an explicit optional zero-mean quadratic prior/penalty on those logs defaults to precision 1 (set to 0 to disable). The implementation rejects inner gradients above its absolute stationarity tolerance and rejects non-positive or excessively ill-conditioned inner Hessians before calculating the exact local implicit hypergradient for **all** MLP weights and biases. `nonlinear_meta_step` averages such gradients over user-supplied task episodes without mutating the starting vector. The caller must enforce support/query and held-out-task separation, provenance and feature preprocessing; a local stationary solution and curvature test do not establish a global inner optimum or calibrated uncertainty.

For development validation, four MLP parameters were checked against central finite differences that re-fit task GP hyperparameters separately at each perturbation; a small synthetic training episode reduced its own query loss after an outer update, and a separate held-out synthetic task produced a finite query loss. Invalid inputs and a deliberately strict curvature limit were rejected. Three targeted tests passed; scoped coverage of this module was 88%. This limited example does not establish transfer improvement, molecular benchmark reproduction or broad numerical reliability. The quadratic prior and simple MLP make this a distinct ADKF-style instance, not a recreation of the paper's molecular architecture or experiments. Independent review is pending.
