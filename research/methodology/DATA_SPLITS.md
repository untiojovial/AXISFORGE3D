# Manifiesto de objetos y separación de datos

Estado: infraestructura diagnóstica; no existe aquí dataset final, separación definitiva ni garantía absoluta de ausencia de fuga. Diseño revisado por auditor independiente antes de implementar. Las pruebas usan exclusivamente fixtures sintéticas.

Cada registro incluye `id`, `family`, `family_evidence`, `origin`, `license`, `license_evidence`, `units`, `split`, `geometry`, `geometry_hash_format` y `sha256`. Para primitivas procedurales coordinadas con robótica, geometría es un diccionario de parámetros en unidades SI, `units="m"`; `canonical-json-v1` significa JSON UTF-8 con claves ordenadas, separadores compactos y sin NaN, cuyo SHA-256 se verifica. No es hash de una malla externa. Los activos externos requerirán implementación adicional que lea y verifique sus bytes reales antes de uso; no se deben representar falsamente como geometría procedimental. La familia asignada por revisión agrupa duplicados y variantes cercanas; sus decisiones y evidencia deben documentarse. Una clase completa como todas las cajas es una agrupación conservadora posible, no un detector de duplicados. Valores desconocidos explícitos bloquean; la función no puede determinar si una afirmación humana es cierta o si dos formas aparentemente distintas son casi idénticas.

Un objeto tiene un solo id y split. Cambios de masa, fricción o posición del centro de masa son condiciones experimentales bajo ese mismo objeto, no objetos independientes. El validador rechaza ids repetidos y coincidencias de digest o familia entre particiones; no inspecciona etiquetas. Revisión de licencias y procedencia debe hacerla una persona con autoridad para determinar derechos: rellenar textos no constituye verificación legal. No declarar CC0 para primitivas propias sin decisión de quien tenga derechos. Detectar o documentar duplicados cercanos requiere análisis externo, en especial de la geometría y sus transformaciones.

`validate_history` requiere observaciones completas del propio objetivo (`kind="observation"`) o tareas históricas completas (`kind="completed_task"`), con tiempo estrictamente anterior al corte, referencias a objetos conocidos y conjunto explícito de splits históricos admitidos. El llamador debe seleccionar `{"train"}` si el protocolo sólo autoriza train: frozen no excluye validation por defecto. `frozen` prohíbe experiencias de otros objetos de test incluso si su split se incluye en la lista; se admiten las observaciones previas del propio objetivo. `online` permite tareas test anteriores solamente si la política fijada de antemano las autoriza: es un protocolo prequential distinto, no test de memoria congelada. Los eventos futuros o simultáneos causan error en lugar de filtrarse silenciosamente. El llamador es responsable de usar exactamente el prefijo validado y de no emplear etiquetas futuras o parámetros ajustados con test; esta API no inspecciona el contenido de las observaciones ni puede demostrar esa propiedad.

Pruebas: `python -m pytest -q tests/phase2/test_dataset_manifest.py` cubre colisiones cruzadas, ids repetidos, evidencia desconocida, alteración del digest, identidad de objetos, igualdad de tiempos, futuro y separación frozen/online. Son fixtures, no división de un único objeto para crear resultados aparentes.

Auditoría independiente: diseño e implementación aceptados para geometría JSON declarada; el auditor reprodujo las tres pruebas y verificó la distinción entre observación y tarea terminada. Esta aceptación no verifica familias, licencias, ausencia de duplicados cercanos ni cumplimiento de políticas fuera de la API.
