# Reach study original implementation

`reach_study_original.py` is the unmodified implementation used for the frozen exploratory study, archived before adding resume support. Its SHA-256 is `cc95dec25ca2e0bdedc80b5bede66e5f809bdce8758941b3d8a6c9cd029433d3`. The original protocol, selection, prequery stamp, 144 observations and aggregate remain unchanged.

The current `research_grasping.phase4.reach_study` serializes measurements under `reach_results.lock`. A first run checks that every selected ID is absent from known caches before writing the prequery stamp. A resumed run validates that stamp, protocol, selection, binary, complete roster, all catalogues and every existing result before further queries. The original twelve results are accepted only if their SHA-256 matches the pinned original report. Newly written partial arms contain checksums for each record and the full arm, a fixed ordered candidate list, and hashes binding the catalogue and selection; they are atomically persisted after each record. These checksums detect accidental corruption; they are not cryptographic authentication against an adversary able to rewrite both content and checksums.

If interruption occurs after the native query/cache commit but before the study row is written, a retry reads that cached observation, preserves its stored cost and marks `cost_provenance` as `recovered_cache_unknown`. It cannot determine actual elapsed time for the interrupted attempt or prove which process generated a previously unrecorded cache file. If interruption occurs before the oracle caches the response, the attempt may have to be repeated and its lost cost cannot be recovered. Record such missing or ambiguous costs rather than treating them as zero or a fresh measured duration. The current resume implementation does not change any of the existing 144 records or their costs.
