En una vista auténtica de fase III el vector global difirió como máximo 1.2e-7 de la extracción anterior y los tokens fueron idénticos; tolerancia afecta operaciones batched. `spatial.py` hace reproyección axial y comprueba oclusión con tolerancia métrica y profundidad válida, aplica transformación explícita de resize/crop/padding y usa una cuadrícula rectangular derivada. No gestiona distorsión ni prueba contacto; ViT conserva contexto global. Prueba adicional confirma equivalencia con la API anterior 7×7 de fase III para su configuración. El estudio `resolution_study.py` compara una misma vista y cámara por objeto de desarrollo: 96×96 ampliado durante el preprocesado frente a render nativo 224×224; las intrínsecas se transforman respetando los centros de píxel. Resultado exploratorio de resolución (22 objetos desarrollo, una vista cada uno): coseno medio 0.8231, mínimo 0.6959 y máximo 0.9247 entre embeddings de 96 ampliado y 224 renderizado; 152.5 s acumulados de render + dos inferencias en CPU. Se comparan imágenes diferentes por resolución y aliasing, con iguales malla, K transformada y pose. El resultado evidencia sensibilidad en este protocolo, no que mayor resolución mejore correspondencia local ni desempeño físico; el test sigue sellado.

## Uso con acceso autorizado

1. Consultar la revisión exacta del repositorio oficial desde un entorno con acceso, por ejemplo `python -c "from huggingface_hub import HfApi; print(HfApi().model_info('facebook/dinov2-small').sha)"`. No registrar ni imprimir tokens. Consultar el README y licencia de modelo y de datos antes de usar o redistribuir. Para DINOv3, la persona autorizada debe solicitar y aceptar sus condiciones por el canal oficial; el código no lo hace.
2. Con el SHA exacto de revisión obtenido oficialmente, ejecutar `python tools/research/phase4/download_models.py --model dinov2 --revision <SHA_40_CARACTERES> --out <DIRECTORIO_LOCAL>`. Para DINOv3 autorizado usar `--model dinov3` y, si procede, proporcionar `HF_TOKEN` en el entorno privado. El script no escribe el token ni baja mirrors. Conservar los hashes JSON que imprime y comprobar la revisión y términos de cada archivo; `local_dir` debe quedar fuera de Git.
3. El adaptador local `load_frozen('dinov2', DIRECTORIO_LOCAL, config_sha256=..., weights_sha256=..., processor_sha256=..., model_revision=SHA)` falla si faltan hashes, si el checkpoint es incompleto o si el procesado espacial no es uno soportado. Para DINOv3 usar `dinov3` solo tras autorización. No se ha probado un checkpoint DINO real en este entorno; la ejecución externa requiere auditoría posterior y no puede declararse completada antes de verificar un bundle recibido.

Resultado auditado v2 versionable: [resolution_96_224_v2.json](resolution_96_224_v2.json), SHA-256 `de0b8f50ad7a4dad86651f35aeee42cf68f38af97cadc565539a0ffe301275f1`. Incluye el hash del manifiesto, checkpoint, fuente, versiones y hash semántico de cada observación de entrada. La licencia de código de OpenCLIP es MIT; los términos específicos de los pesos y del dataset asociado requieren evaluación independiente, no se presume que coincidan con el código.

La extensión [resolution_96_224_patches.json](resolution_96_224_patches.json) (SHA-256 `5a84f82ac1dfd71687131aded9dfbe81aeec654fb93fe40ee0334e438775807d`) compara también los 49 tokens coincidentes de cada vista: coseno medio descriptivo 0.8688, con medias por objeto entre 0.8018 y 0.9239. Incluye patches de fondo y tokens dependientes mediante atención global; no son 1.078 observaciones independientes, ni mide correspondencias de contacto ni mejora de agarre.

El procesador rápido DINOv3ViT de Transformers 4.57.3 redimensiona directamente una imagen a alto y ancho fijos. El adaptador incorpora ese caso y contrasta el tamaño con el tensor real. La prueba local usa el procesador nativo, dos tokens de registro y una rejilla rectangular en un modelo pequeño de pesos aleatorios. El adaptador de la extracción OpenCLIP anterior se conserva en el commit `3ac8292`, en la misma ruta. Las dos implementaciones se verifican con las características originales. La fuente de pesos DINOv2 siguió devolviendo HTTP 403 al reanudar el entorno.
